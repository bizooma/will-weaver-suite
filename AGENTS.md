
- SEO canonicals/og:url are pinned to https://amicusedge.com (SEOHead SITE_ORIGIN), never window.location.origin — preview domains must not self-canonicalize.
- public/sitemap.xml is the prerender route list (scripts/prerender.mjs); add a route there to both index and prerender it.
- Website Manager (src/components/dashboard/website/): section types and content keys in types.ts/sectionContent.ts are a contract with the public site renderer — change both together; publish eligibility lives only in canPublish.ts. Why: the renderer reads exact jsonb keys and hosting entitlement will be wired in one place.
- Pure-logic tests live in tests/*.test.ts and run with `bun test ./tests/<file>` (Bun's built-in runner, no npm test package). Why: src/ is type-checked without Bun types.
- The public firm sites are rendered from the newest `firm_site_publishes.snapshot`, never from the live `firm_site_pages`/`firm_site_sections` tables. Changing `SiteSnapshot` in publishSite.ts is a breaking change to the renderer: bump its `version` and ship the renderer first, or published sites stop rendering. Why: publish is a deploy, so a saved draft must not change what visitors see.
- Move a page's `is_home` flag only via `supabase.rpc("set_firm_site_home_page", ...)`, never with two UPDATEs. Why: `firm_site_pages_one_home` is a non-deferrable partial unique index, so clear-then-set across two requests leaves a window with no home page and the renderer resolves "/" by `is_home`.
- The published-site zone is `siteRules.SITE_BASE_DOMAIN` (`sites.amicusedge.com`); build public site URLs only with `liveSiteUrl()`, never by hand. Why: it must stay in step with `SITE_BASE_DOMAIN` in the firm-site-renderer Worker, which is what resolves a hostname to a site — a mismatch advertises a URL that serves nothing.
